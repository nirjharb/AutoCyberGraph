# AutoCyberGraph — Engineering Decisions (ADR log)

> Rule from the brief: when multiple technically reasonable choices exist, pick
> the simplest reliable one and record it here. Do not block on minor
> engineering decisions.

## ADR-001 — Database: SQLAlchemy 2.0 over SQLite locally, PostgreSQL in production
**Context:** The sandbox has no PostgreSQL server or Docker. The brief requires
PostgreSQL as primary DB.
**Decision:** One SQLAlchemy 2.0 model layer, portable across engines.
`DATABASE_URL` selects the engine: default `sqlite:///./autocybergraph.db`
(local/demo), `postgresql+psycopg://…` in production. Docker Compose and
`.env.example` wire PostgreSQL for deployments.
**Consequences:** Zero-friction local demo; production uses managed Postgres
exactly as specified. Graph queries are computed in the service layer, keeping
the schema ANSI-portable (no PG-only SQL in application code).

## ADR-002 — Graph: service-layer traversal now, Neo4j-ready abstraction
**Context:** Brief prefers PostgreSQL unless Neo4j becomes clearly easier; it
requires a graph abstraction layer either way.
**Decision:** `GraphService` protocol (`app/graph.py`) exposing `neighbors()` /
`bfs()` with typed edges + reasons. MVP implementation derives adjacency from
relational rows. A future `Neo4jGraphService` implements the same protocol.
**Consequences:** Change Impact Engine and Evidence Graph depend only on the
protocol; swapping the backing store is additive.

## ADR-003 — Auth: JWT (HS256) + bcrypt + dependency-injected RBAC
**Context:** Brief allows JWT or secure sessions. Frontend and backend are
separate deployables (Vercel + Railway/Render).
**Decision:** Stateless JWT access tokens (env `JWT_SECRET`, expiring `JWT_TTL`),
bcrypt cost 12, role checks via FastAPI dependencies. No refresh-token rotation
in MVP (short TTL); documented as roadmap hardening.
**Consequences:** Simple, standard, works cross-origin with an explicit CORS
allowlist.

## ADR-004 — UI kit: local shadcn-style components instead of the shadcn CLI
**Context:** shadcn CLI is interactive and pulls many dependencies; sandbox
constraints favor deterministic installs.
**Decision:** Small, consistent, locally-owned component library (button, card,
badge, table, dialog, input, select, tabs, toast) with Tailwind. Same visual
quality bar, zero generator friction.
**Consequences:** Fewer deps, full control, faster builds.

## ADR-005 — Cytoscape.js for graphs
**Context:** Need evidence-graph + vehicle network visualization.
**Decision:** Cytoscape.js (mature, purpose-built, tree/layered layouts) rather
than React Flow (better for editing) — we render read-only navigable graphs.
**Consequences:** Click-node → detail navigation implemented via router.

## ADR-006 — TARA risk method: configurable matrix, honestly documented
**Decision:** `risk = f(impact, attack_feasibility)` matrix → LOW/MEDIUM/HIGH/
CRITICAL, defined in `services/risk.py` and documented in `docs/tara.md` as an
application implementation, configurable per organization — **not** an official
ISO/SAE 21434 certification methodology.
**Consequences:** Deterministic, testable, honest.

## ADR-007 — CyberAdvisor: deterministic DB-grounded query engine (LLM-ready adapter)
**Context:** "Fake AI responses" are forbidden; answers must be grounded in
application data; the phrase "Insufficient evidence in the project database."
must be used when the system cannot determine an answer. No AI API key exists in
this environment.
**Decision:** A rule-based query engine over live API data with an intent
classifier (keyword/pattern matching over 10+ question families). An
`AdvisorBackend` protocol allows an LLM backend later (`AI_API_KEY`), with the
grounding + refusal contract enforced around any backend.
**Consequences:** Every answer cites real entity IDs/links; zero invented
compliance conclusions; no key required for the demo.

## ADR-008 — SBOM: CycloneDX first, SPDX architected behind one parser interface
**Decision:** `services/sbom.py` exposes `parse_sbom(text, fmt)`; CycloneDX JSON
1.4/1.5 parsed robustly (components, versions, hashes, purls, licenses); SPDX
JSON parsed at the document/package level. Both feed the same normalized
`SbomComponent` model. Format auto-detected from content when not specified.

## ADR-009 — Migrations: Alembic scaffold + `create_all` bootstrap
**Decision:** `Base.metadata.create_all()` on startup for zero-friction demo
boot; Alembic env wired to the same metadata with an autogenerated baseline for
production CI (`alembic upgrade head`). Rationale: hand-writing a 20-table
migration without a live PG in the sandbox risks drift; autogenerate against the
canonical metadata avoids divergence.
**Consequences:** Demo boots anywhere; production path is standard.

## ADR-010 — Demo data via idempotent seed script
**Decision:** `backend/app/services/seed.py` (invoked by `scripts/seed.sh` or
`POST /api/admin/seed` in dev) builds the full Demo EV Platform dataset,
including the *Gateway ECU crypto library v2.4 → v2.5* change. Idempotent
(re-running does not duplicate).
**Consequences:** "Reset demo" is one command; tests reuse the same factory.

## ADR-011 — File storage: references, not blobs (MVP)
**Decision:** Evidence records store `file_reference` (URI/URN/path) + metadata;
upload endpoints validate type/size and store metadata with an `uploads/`
directory hook. Object storage (S3-compatible) is a config swap (`STORAGE_*`
env vars), documented in `docs/security.md`.
**Consequences:** Keeps MVP deployable everywhere; no credentials required.

## ADR-012 — Deployment target: containerized backend + static frontend
**Decision:** Dockerfile for backend (python:3.12-slim, non-root user), Vercel
config for frontend, `docker-compose.yml` with PostgreSQL for self-hosters.
FastAPI also serves the built frontend (`frontend/dist`) when present — this is
how the live demo runs (single origin, no CORS issues).

## ADR-013 — Test stack: pytest + httpx for API, Vitest for frontend units
**Decision:** Backend: pytest + FastAPI TestClient (auth, RBAC, risk, trace,
impact, gate, SBOM, integration). Frontend: Vitest + Testing Library for login
flow, traceability rendering, change-impact display, release-gate display.
CI runs both plus lint and a basic security check (pip-audit/npm audit band).

## ADR-014 — Python 3.13 compatibility
**Context:** Sandbox ships Python 3.13; some security libs lag.
**Decision:** Use `PyJWT` + `bcrypt` directly (not passlib/python-jose pin
chains), SQLAlchemy ≥2.0.36, pydantic ≥2.10. Verified against 3.13 in CI
matrix (3.11–3.13).
