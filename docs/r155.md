# UNECE R155 Mapping Layer

> AutoCyberGraph does **not** automatically prove regulatory compliance with
> UNECE R155 and does not replace a Cyber Security Management System (CSMS).
> R155 content is represented as a **reference/mapping layer** to organize
> engineering evidence. Official text: https://unece.org/transport/vehicle-regulations

## What the layer provides

An evidence organization pattern:

```
R155-related Evidence → Process → Risk → Control → Vehicle → ECU → Evidence
```

Representative process clauses in the demo catalog:

| Clause | Title |
|--------|-------|
| R155-7.2.2.2 | CSMS processes |
| R155-7.2.2.3 | Risk assessment and management |
| R155-7.2.2.4 | Security by design |
| R155-7.2.2.5 | Post-production monitoring |

## How it is used

- `ComplianceMapping` rows with `standard="UNECE R155"` attach clauses to
  application entities (evidence items, requirements, releases…)
- The mapping carries `mapping_type` (`trace | evidence | concept | process`),
  `confidence` and free-text `notes` — an engineering annotation, not a
  legal conclusion
- The supplier portal and evidence module produce the raw material
  (SBOMs, test results, TARA evidence) that an organization can assemble into
  its own regulatory submissions **outside this tool**

## What the application will never do

- Claim "R155 compliant" or issue any compliance verdict
- Substitute for a CSMS audit, type approval or regulatory review

## API

- `GET /api/mappings?standard=R155`
- `POST /api/mappings` — create mapping annotations
