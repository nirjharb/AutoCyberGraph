# UNECE R156 — Software Update Evidence Workflow

> AutoCyberGraph organizes software-update security evidence as an engineering
> workflow. It does **not** prove compliance with UNECE R156 and does not
> replace a Software Update Management System (SUMS).

## The workflow

For every software release:

```
Release
  ↓
Changed components        (via Change records)
  ↓
Security impact           (Change.security_assessment — R156-style assessment)
  ↓
Testing                   (TestCase → TestResult)
  ↓
Approval                  (Cybersecurity Release Gate)
  ↓
Evidence                  (Evidence linked to release/requirement)
```

## What is tracked per release

- software version + release type (`PRODUCTION | PATCH | OTA | DEVELOPMENT`)
- ECU (and thus vehicle)
- package/SBOM availability
- changes with security-impact assessment
- tests and their results
- approval state (release status + gate result)
- evidence artifacts

## Demo link

The flagship demo change (`crypto library v2.4 → v2.5`) carries an explicit
`security_assessment` text; the release gate's `security_impact` check fails
until every change in scope has a completed impact analysis — exactly the
evidence discipline an R156-style process demands.
